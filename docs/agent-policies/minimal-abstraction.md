# Minimal Abstraction Policy

현재 작업에서 확인된 요구만 구현한다.

## 추상화 도입 조건

새로운 범용 타입, 규칙 엔진, 변환 계층은 다음 중 하나를 만족할 때만 추가한다.

1. 현재 저장소에 동일한 변화 축을 가진 실제 사용 사례가 두 개 이상 존재한다.
2. 사용자가 이번 작업 범위로 명시적으로 요청했다.
3. 기존 공개 계약을 유지하기 위해 반드시 필요하며, 그 계약을 구체적으로 제시할 수 있다.

향후 다른 템플릿에서 필요할 가능성만으로는 추상화를 추가하지 않는다.

## 호환성

기존 테스트가 존재한다는 이유만으로 해당 입력 형식을 공개 계약으로 간주하지 않는다.
테스트 실패 시 먼저 테스트가 사용자 계약을 보호하는지, 이전 구현 세부사항을 보호하는지 구분한다.

## 데이터 경계

입력은 한 방향으로만 변환한다.

```text
원본 입력 → 검증된 의미값 → 렌더링 계획 → 출력
```

정규화된 값을 다시 사람용 입력이나 구형 구조로 복원하는 코드는 원칙적으로 추가하지 않는다.

## 정지 조건

다음 상황이 발생하면 구현을 중단하고 추가 구조의 필요성을 먼저 보고한다.

- 요청되지 않은 범용 타입이 3개 이상 필요함
- 새로운 범용 파서 또는 규칙 엔진이 필요함
- 원본 또는 구형 입력 구조로의 역변환이 필요함
- 기존 계획보다 수정 범위가 크게 증가함
- 미래 사용 사례를 이유로 현재 코드가 늘어남
